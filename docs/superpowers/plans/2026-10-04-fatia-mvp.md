# Allot MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and publish a Devnet-only payment link that atomically splits test USDC among 2 to 5 Solana wallets and exposes a public on-chain receipt.

**Architecture:** A Next.js App Router application uses one browser wallet-backed Solana Kit client. Payment configuration travels as validated base64url JSON, pure `bigint` functions calculate shares, one transaction contains idempotent ATA creation, checked transfers, and a memo, and the receipt reconstructs balances from RPC data.

**Tech Stack:** Next.js 16.3.8, React 19.3.0, TypeScript, Tailwind CSS, Solana Kit 8.4.0, Solana Kit RPC 0.19.0, Wallet plugin 0.20.0, Solana React 8.4.0, Token client 0.17.0, Memo client 0.15.0, Zod 4.6.5, Vitest 5.0.3, npm.

**Spec:** `docs/superpowers/specs/2026-10-04-fatia-mvp-design.md`

## Global Constraints

- Use Solana Devnet only.
- Use Circle test USDC mint `4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU` only.
- Use `bigint` base units for every money calculation; USDC has 6 decimals.
- Never access or store private keys.
- No backend, database, login, custom on-chain program, mainnet, custody, or real Pix.
- UI copy is PT-BR; code identifiers are English.
- Accept 2 to 5 unique recipients whose basis points total 10000.
- Minimum payment is 1 USDC.
- The payer funds missing recipient ATAs.
- Every simulated feature must say `Simulação para demonstração`.
- Preserve a returned signature when confirmation fails.
- Keep the core usable at 375 px and respect `prefers-reduced-motion`.

## Review Focus

- A corrupted or non-canonical base64url payload must produce a safe PT-BR error, not partial data.
- A valid Solana address repeated with different names must still be rejected as a duplicate.
- Integer division must preserve the exact total when several recipients round down.
- A network failure after submission must expose the known signature and prevent blind retry.
- A transaction without an Allot memo must still render balance changes without inventing a title.
